# Contributing

Start with an issue describing a question, correction or proposed resource. Include the audience, intended benefit, relevant sources and a manageable scope. Avoid duplicating existing work without explaining the added value.

For a direct edit, branch or fork, copy the relevant template, edit its JSON front matter and submit a pull request. Assign a unique resource identifier and use stable filenames. Use UK English and explicit source versions. Page links should use Jekyll `relative_url`; do not hard-code the deployment path.

An editor can submit agreed contributions for people who do not use GitHub. Confirm their preferred attribution and permission to publish. Never invent consent or an organisation's endorsement.

AI assistance is welcome when disclosed. Verify claims and citations, identify uncertainties and retain human responsibility. Do not upload patient data, credentials, confidential minutes or unlicensed source documents.

Check `LICENSE.md` before accepting third-party contributions. Until terms are agreed, contributors must explicitly confirm permission for repository and website publication; do not imply a broader reuse grant.

For review: use `templates/review.md`, run the checks in README, and explain changes in the pull request. Substantive changes require a human reviewer other than the author. Readers can use the configured public editorial contact; no contact address has been invented in this starter.
